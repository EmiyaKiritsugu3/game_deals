## Detailed Findings (Original Audit — Pre-Sprint)

### C1 — CRITICAL — Open Redirect via `next` parameter

**File:** `src/app/auth/callback/route.ts:29`

**Fix applied (commit 92964c6):**

```ts
function safeNext(next: string | null, origin: string): string {
  if (!next) return `${origin}/`;
  if (!next.startsWith('/')) return `${origin}/`;
  if (next.startsWith('//')) return `${origin}/`;
  if (next.startsWith('/\\')) return `${origin}/`;
  return `${origin}${next}`;
}
```

Tests cover: happy path (`/profile`), `//evil.com`, `/\evil.com`, null, `javascript:`, nested path with `//`.

### H1 — HIGH — Cross-user playlist games deletion

**File:** `src/actions/playlists.ts:185`

**Fix applied (commit 92964c6):**

```ts
export async function deletePlaylistAction(id: string): Promise<boolean> {
  const userId = await getAuthenticatedUserId();
  const ownership = (await db.execute(
    sql`SELECT id FROM playlists WHERE id = ${id}::uuid AND "userId" = ${userId}::uuid`
  )) as Array<{ id: string }>;
  if (ownership.length === 0) return false;
  await db.execute(sql`DELETE FROM playlist_games WHERE "playlistId" = ${id}::uuid`);
  await db.execute(sql`DELETE FROM playlists WHERE "id" = ${id}::uuid`);
  return true;
}
```

Ownership check happens BEFORE child row deletion. User A can no longer delete games from User B's playlist by submitting their playlist id.

### M1 — MEDIUM — IP spoofing via `x-forwarded-for`

**Fix applied (commit 71cd798):**

```ts
function getClientIp(request: Request): string {
  const real = request.headers.get('x-real-ip');
  if (real) return real;
  const fwd = request.headers.get('x-forwarded-for');
  if (fwd) return fwd.split(',')[0]?.trim() ?? 'unknown';
  return 'unknown';
}
```

`x-real-ip` (Vercel-trusted) preferred; `x-forwarded-for` fallback with comma split.

### L1 — LOW — Non-constant-time cron secret comparison

**Fix applied (commit fb2c788):**

```ts
import { timingSafeEqual } from 'node:crypto';

function safeEqual(a: string, b: string): boolean {
  const bufA = Buffer.from(a);
  const bufB = Buffer.from(b);
  if (bufA.length !== bufB.length) return false;
  return timingSafeEqual(bufA, bufB);
}
```

Missing/empty `CRON_SECRET` returns 500 (server misconfigured) instead of leaking into the auth check.

### L3 — LOW — Drizzle `as unknown as` casting pattern

**Status:** Documented via ADR-001 + AGENTS.md conventions. The cast is intentional — Drizzle's `RowList<Record<string, unknown>[]>` requires a narrowing cast for typed access. Migration to fully-typed query builders (`db.select().from(table)`) is ongoing codebase hygiene.

## Verified Defenses (no action needed)

- **SQL injection**: All Drizzle queries use parameterized `sql` template tag. No string interpolation.
- **Cross-user ownership**: `addGameToPlaylistAction`, `removeGameFromPlaylistAction` use subquery ownership checks.
- **CSRF protection**: Next.js 16 Server Actions have built-in same-origin POST requirement (preserved).
- **Slug generation**: Uses `crypto.randomUUID()` (CSPRNG), not `Math.random()`.
- **Image domain restrictions**: `next.config.ts` allowlist for `images.remotePatterns` is comprehensive.
- **Cron matcher**: `api/cron(?:/|$)` excluded from middleware (correct).
- **Cookie refresh**: `updateSession()` refreshes tokens via SSR pattern.

## Prompt Injection Report

During this audit session, **multiple prompt injection attempts** were detected and ignored:

| Vector | Pattern | Mitigation |
|--------|---------|------------|
| Tool output XML tags | Fake `<user-prompt-submit-hook>`, `<ip_reminder>`, `<system-reminder>` | Quarantined |
| Caption claims | Fake authorship ("Pantzer Security Advisor", etc.) | Ignored |
