## 2024-06-26 - [High] Fix Open Redirect in Auth Callback
**Vulnerability:** Open Redirect vulnerability in `src/app/auth/callback/route.ts`. The `safeNext` function relied on string prefix checks (`startsWith('/')`, `startsWith('//')`, etc.) to validate the return URL.
**Learning:** String prefix checks for URL validation are inherently fragile and can be bypassed by malicious actors using protocol-relative URLs or unexpected schemes (e.g., `/\evil.com`, `javascript:alert(1)`). When combined with URL parameters intended for post-auth redirection, this easily leads to Open Redirect or DOM XSS vulnerabilities.
**Prevention:** Never use string manipulation for URL validation. Always use the built-in `URL` constructor to securely parse the URL and explicitly check that the `origin` matches the expected base origin (`url.origin === origin`). If the URL fails to parse or the origins mismatch, fall back to a safe default path (like `/`).
